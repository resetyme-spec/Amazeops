📋 Implementation Phases

1
Foundation — Shared Infrastructure
Build the core backend + auth + data models that all three apps depend on.
  • Extend Firebase Firestore schema — new collections: users, roles, permissions, activityLogs
  • Build RBAC system — roles: admin, staff, partner with granular permissions
  • Extend order model — add qcStatus, qcPhotos, deliveryStatus, acceptedAt, qcRejectedAt
  • Extend garment model — add brand, comments, photos{front,back,other}, qcNotes
  • Build Cloud Functions — auth hooks, activity logging, status-change triggers
  • Extend Dummy API — add endpoints for orders-by-partner, QC actions, activity logs
2
Admin Portal — User & Permission Management
Give admins full control over who accesses what.
  • New page: Users — CRUD for Staff & Partner users
  • Per-user config: role, assigned orders, module access, action permissions
  • New page: Roles & Permissions — define role templates
  • New page: Activity Logs — complete audit trail viewer
  • Order assignment — admin assigns orders to specific partners
  • QC configuration — set photo requirements per customer category
3
Partner Mobile App
React mobile app for partners to process orders on their phones.
  • Auth — phone/email login, role-based routing
  • Dashboard: New Orders, In Progress, QC Pending, QC Rejected, QC Approved, Delivery Pending, Completed
  • Order Detail: garment list, QR codes, customer category, processing info
  • Accept Order: status ASSIGNED → IN_PROCESS
  • QC Form: per-garment — brand, comments, front/back/other photos
  • Photo validation — mandatory for Signature Care & L'Amaze Prive
  • Send for QC: submit with all required data → status QC_PENDING
  • QC Rejected view: see rejection reason, correct, resubmit
  • Delivery Initiation: after QC_APPROVED, mark as delivery started
4
Staff Mobile App
React mobile app for staff to review QC, monitor orders, manage delivery.
  • Auth — phone/email login, role-based routing
  • Dashboard: QC Pending queue, Completed QC, All Orders
  • QC Review: view partner-submitted data + photos per garment
  • QC Approve: QC_PENDING → QC_APPVED, trigger notification to partner
  • QC Reject: QC_PENDING → QC_REJECTED with reason + comments
  • Order Monitor: view all assigned orders, status tracking
  • Delivery Initiate: mark QC_APPROVED orders as out for delivery
5
Notifications & Real-time Updates
Keep everyone in sync with live updates.
  • Firestore real-time listeners on order collections (per-user filtered)
  • Push notifications — QC status changes, new assignments, rejections
  • In-app notification center for both Partner & Staff apps
6
Testing & Deployment
Polish, test, and go live.
  • End-to-end testing of full order lifecycle
  • Permission testing — verify data isolation between partners
  • Photo upload testing — validate mandatory photo enforcement
  • Activity log verification — ensure all actions are captured
  • Build mobile apps (Capacitor / React Native / PWA)
  • Deploy & onboard first batch of partners & staff

📁 New Project Structure

Two new React apps will be created alongside the existing admin portal:
  • web/ — Admin Portal (existing, will be extended)
  • partner-app/ — New React app for Partners
  • staff-app/ — New React app for Staff
  • functions/ — Cloud Functions (extended)
  • shared/ — Shared types, utils, components across all apps

🗄 Data Model Changes

New Collections

  • users — id, name, email, phone, role (admin/staff/partner), assignedOrders[], permissions{}
  • roles — id, name, permissions[], description
  • activityLogs — userId, userName, role, action, orderId, subOrderId, previousValue, newValue, comments, timestamp

Order Model — Extended Fields

  • qcStatus — PENDING / APPROVED / REJECTED
  • qcRejection — { reason, comments, rejectedBy, rejectedAt }
  • deliveryStatus — PENDING / INITIATED / COMPLETED
  • acceptedAt — timestamp
  • assignedPartnerId — link to partner user

Garment Model — Extended Fields

  • brand — string
  • comments — string
  • photos — { front: url, back: url, other: url }
  • qcNotes — string (staff QC comments)
